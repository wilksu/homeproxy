# 开发、安装与验收

目标设备为 ImmortalWrt 25.12 / MT7986A、128 MB Flash、512 MiB RAM。核心固定 sing-box 1.14.0，具体包版本来自 pairing.mk 和 compat.json。

## 开发与打包

本地仅做脚本、语法、浏览器及已有二进制验证，不构建安装包或编译工具。CI 生成 protobuf 浏览器资源及安装包。

快捷打包脚本 `.github/build-ipk.sh` 的 APK/IPK 两种路径现在均输出：

- `luci-app-homeproxy`：主体网页、脚本、权限及配置，不含翻译 LMO。
- `luci-i18n-homeproxy-zh-cn`：当前仓库提供的中文翻译，依赖主包；今后 po 下增加语言时逐语言分包。
- sing-box 是独立依赖，不装进主包。配套 SDK 工作流构建核心、主包和选中的中文包，不再构建本地 Dashboard 包。

PR 自动运行 Python 回归和快捷 APK/IPK 打包；耗时较长的配套 SDK/核心构建改为手动触发。脚本或界面修改可复用已构建的 1.14.0 配套核心，无需重新编译核心。

下载工作流的 `homeproxy-apk` / `homeproxy-ipk` 归档后可得到主包和中文包。上传步骤仅匹配 `.github` 中对应后缀的安装包，显式允许该隐藏目录；缺少产物时直接失败，避免构建状态成功却没有下载文件。

`tests/test_package_layout.py` 使用模拟的打包器和翻译器执行目录整理、检查主包/语言包隔离；不会编译翻译或生成真实 APK/IPK。它不能替代 CI 和软件包安装验证。

## 安装策略

当前按全新安装验收，不承诺从旧 HomeProxy 配置无损升级。已删除本次新增的 schema114 转换、迁移备份/报告及旧订阅 ID 自动映射；原项目历史迁移仍保留，不能据此认为支持旧配置。

卸载软件包可能保留配置文件。全新安装应使用新默认配置、重新订阅/创建节点，而不是直接继续使用遗留 `/etc/config/homeproxy`。本次没有删除用户容器的配置、节点或历史备份。

正常的新版本内订阅刷新、来源隔离、依赖检查、本地覆盖保留不属于旧版本迁移，仍保留。

安装脚本初始化 API 密钥；启动仍先检查候选配置和核心版本。该检查保护运行服务免受明显错误配置影响，不是运行时网络健康自动回滚。

## 观测日志和生命周期

sing-box 1.14.0 attached API 默认在核心内保留 3000 条日志；SubscribeLog 先发送 reset=true 的缓冲快照，再发送实时记录。浏览器保留显示副本（最多 3000 条，最多显示 1000 条），重连快照替换旧副本。

ClearLogs 清理核心内存缓冲，并向订阅者发送 reset；它不会截断磁盘/文件日志。当前页面没有清除按钮。文件日志在 /var/run/homeproxy 下，由 clean_log.sh 单独定期轮转，供启动或 API 故障排查。

LuCI 转发鉴权并限制持久流：同一会话最多 1 条，全局最多 2 条；普通短请求不计入持久流名额。日志/连接采用最长 45 秒的直接流，断线后重新鉴权；CGI 退出后看护进程结束 curl。没有响应数据文件、offset 或 500 ms 轮询。短快照最多等待 5 秒。

Overview 用 LuCI poll，每秒取得快照，以总流量差/实际时间计算速率；Groups 进入和操作后取快照，URLTest 后在 1、3、6、16 秒做有界刷新；Tools 空闲只取快照，测试互斥；Diagnostics 保持单次 RPC。日志暂停会停止订阅，恢复重取核心缓冲。401/403 和配额持续耗尽后停止自动争抢。

## 订阅事务与下载路径

订阅在私有 UCI 目录中更新，候选生成和核心检查通过后才原子替换正式配置。检查到未提交更改或更新期间的配置变化会拒绝提交。失败不会用旧备份覆盖用户的新修改。这是日常更新事务，不是旧版本迁移。

关闭“通过代理更新”暂时恢复原有语义：如客户端运行则临时停止 HomeProxy（包括其服务端），下载使用直接 curl，退出/失败时恢复。此模式会短暂中断代理；尚未改成无中断的防火墙标记下载。开启时显式用本机 mixed 入口 SOCKS5h，目标域名由代理解析。没有代理时不静默回退直连。

外部 API TLS 支持独立的证书域名，curl 使用该域名校验并通过 resolve 连接实际监听 IP，不关闭证书校验。

## 第二轮 review 修复

订阅 updater 的执行权限只授予 HomeProxy 写角色；只读页面禁用更新和删除入口。批量删除订阅节点前检查默认出站、路由、DNS、规则集、手动组、拨号及引用节点；存在引用时拒绝删除并展示位置。

远端订阅禁止 Tailscale，不能通过自动更新控制 SSH、系统接口、路由通告或状态/文件接收目录。本地手动 Tailscale 保留；此前存储的带订阅来源 Tailscale 也拒绝生成。

事务记录更新前客户端和服务端的实际状态。无变化的代理下载更新不重启；直连下载已经临时停机时只恢复原有实例。原本停止或完全禁用时仅保存，不自动启动；仅服务端运行时不为客户端节点更新重启它。同步激活失败时恢复原配置与原实例；回滚发现更新后的并发配置修改时不覆盖，保留私有恢复文件并报告。

Python suite 通过可复用工作流进入两个构建工作流的前置检查。CI 提供固定 hash 的 ucode 源码和 sing-box 1.14 二进制；测试发现任何跳过、缺失依赖或错误核心版本均失败。本地仍不编译。

## 最后一轮修复与验证

- 实例恢复标志在候选生成前就生效，防火墙入口也使用相同选择，并清理未选实例的残留生成文件。未运行且配置有误的另一实例不会阻止恢复。
- DNS 响应过滤的 evaluate 保留可安全前置的请求条件，缓存、超时等查询选项放在 evaluate 上，避免 respond 带不支持的字段。普通域名过滤不会向评估服务器发送无关域名。整体取反不能简单缩成请求条件取反；规则集还可能合并地址/端口匹配组，因此这些组合保留完整响应判定，仅前置确定独立的请求条件，不解析或改写远端规则集。
- 单个节点删除复用批量删除的引用检查；先解除默认出站、组、DNS 等引用再删除。只读会话不能执行删除。
- 定时更新在资源列表变化、订阅未变化时也激活一次；不重复重启、不启动原本停止的客户端，也不为此重写未变化的 UCI 文件。
- 回滚的临时文件创建、复制、权限设置和替换均显式传播错误，失败保留恢复配置。
- VMess 入站仍使用官方 `alterId`，出站才使用 `alter_id`。非零入站值已通过 1.14.0 核心检查，这一 review 建议不适用。

本轮完整回归为 41 项 Python、27 项 JavaScript，通过且没有跳过。订阅矩阵扩展为 4 种运行状态 × 8 种结果 × 2 种下载路径 × 2 种资源变化状态；另执行真实 init 准备函数、真实防火墙生成器和回滚故障注入。DNS 使用两个本地 UDP 解析器与官方核心运行，验证实际查询去向，以及取反/混合规则集不会漏匹配。

容器实际 LuCI 页面验证了被引用节点拒绝删除、未引用节点走正常删除入口，无脚本异常；使用仅浏览器内的临时节点并拦截保存，没有修改容器持久配置。

# 链式出站与引用节点

节点设置的“上游出站”表示通过另一个节点／组连接本节点服务器。A 的上游是 B 时，流量路径为路由器 → B → A → 目标。它对应原生 detour，代理协议类型保持原样。留空继承原值；“直接连接”明确清除原来的上游。

手动节点新增“创建方式”：直接配置／引用已有节点。引用方式选择基础节点并继承服务器、认证、TLS、传输等参数，只编辑名称和本地覆盖项（上游、接口、解析器、解析策略）。生成器将其展开成独立标签的普通出站，核心没有新增协议类型。当前基础限定为普通代理出站，不支持以 Selector、URLTest、WireGuard 或 Tailscale Endpoint 为基础；组可以作为上游。

引用通过 node_base 保存稳定 ID，不复制订阅密码。基础节点更新时继承新配置；引用节点是独立的本地记录，订阅更新不会覆盖其设置。直接编辑订阅节点上的 local_detour/local_bind_interface/local_domain_resolver/local_domain_strategy 也会在后续订阅更新中保留。来源自带的 node_detour 保留原值，local_detour 仅作本地覆盖；订阅条目不能切换成引用创建方式。

自定义模式和普通主节点／UDP 模式共用节点展开及依赖检查。生成前检查缺失引用、空组、默认成员和引用／组／detour 混合循环；UI 在基础节点、上游和成员编辑时也检查。基础节点只作为参数来源，不因被引用而额外生成；真正的上游与组成员会被递归加载。自定义 DNS 解析器若在当前模式没有生成，则明确拒绝配置，不静默回退。

旧“路由节点”标签已移除，新建和编辑统一在节点设置。生成器仍兼容旧 routing_node 存量记录：非空覆盖项继续生效，未填的覆盖项继承节点本身；当前开发容器没有此类记录需要迁移。统一“启用即加载”的策略调整尚未实施。

直接配置表单顺序为名称、创建方式、类型及协议参数；上游、解析器和接口覆盖项放在末尾的“高级连接设置”下。引用方式显示基础节点和覆盖项，不重复显示协议参数；基础节点必须明确选择，继承摘要随选择更新。

验证：生成器覆盖自定义／普通主节点的引用与上游加载，核心 check 通过；模型测试覆盖基础更新、清除继承上游、缺失引用及混合循环。浏览器验证引用创建表单与保存，以及普通节点的循环阻断。未使用用户代理做真实双跳数据面测试。

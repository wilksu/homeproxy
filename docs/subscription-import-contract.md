# 原生订阅导入的数据约定

导入不是 JSON 原文透传。只有能由节点模型、编辑器和生成器共同保留含义的配置才接受；不支持的字段明确拒绝，原有节点由更新事务保留。核心接受原始配置，只证明输入有效，不能证明转换后的配置或页面保存结果正确。

## 归一化边界

归一化放在 `node_import.uc`，在写入 UCI 前完成。UCI 中只存表单能表示的字符串和非空字符串列表，不存 JSON `null`、嵌套对象或含混的单选数组。

| 原生输入 | 节点模型中的表示 |
| --- | --- |
| Shadowsocks `network` 为 `tcp`、`udp` 或对应单元素数组 | 单个协议字符串 |
| 两种协议的数组（顺序不限）、空数组、`null`、缺省 | 不设置限制，使用核心默认的 TCP 和 UDP |
| 重复的相同协议 | 去重后使用单个协议字符串 |
| 可选字段的合法 `null`、可选列表的空数组 | 不写入对应 UCI 选项 |
| ALPN、SSH 密钥等列表字段的单值或数组 | 统一为有序列表；拒绝页面无法保留的空项、非字符串项 |
| TLS uTLS 的 `enabled` 缺省、`null` 或 `false` | 保持关闭；不会凭空启用指纹 |
| 1.14.0 中等价于 Chrome 的五个兼容指纹名称 | 规范名称 `chrome`，编辑器可识别 |
| HTTP 传输的 Host 请求头 | 有序字符串列表；WebSocket、HTTP、HTTPUpgrade 使用列表编辑器 |
| 显式关闭 UDP 分片 | 保留 `0`，生成 `false`，不能用缺省代替 |
| VMess 缺省的 global padding | 显式保存关闭，避免编辑器的新建节点默认值将其开启 |
| 空的 detour 或分组默认值 | 不设置显式引用，使用核心默认行为 |
| Hysteria 同时提供 `auth_str`、`auth` | 按核心规则优先使用非空 `auth_str`，不依赖 JSON 键顺序；都为空时保持无认证 |

空值归一化不会绕过对原始输入的核心检查：例如核心不接受 `routing_mark: null` 或空的超时值时，导入仍然拒绝。不支持的其他传输头也仍然明确拒绝。数组中的非字符串和不能表示的对象不会通过字符串拼接存入 UCI。

上述核心语义以配对的 sing-box 1.14.0 为准：[NetworkList](https://github.com/SagerNet/sing-box/blob/v1.14.0/option/types.go)、[uTLS 指纹实现](https://github.com/SagerNet/sing-box/blob/v1.14.0/common/tls/utls_client.go)、[VMess 默认值](https://github.com/SagerNet/sing-box/blob/v1.14.0/protocol/vmess/outbound.go)。升级配对核心时需要重核这些约定。

## 验证要求

自动测试的分层、运行命令和各项防护对应的断言见[测试说明](testing.md)。单元测试应独立于应用安装和服务状态，不向应用加入测试专用分支。

新增导入字段时，需要覆盖原始 JSON → 导入模型 → 实际生成器 → 配对核心检查，并断言配置含义。只断言核心返回成功会漏掉协议限制、布尔默认值等被改变的问题。

影响编辑器的字段还要验证页面无改动保存、刷新后的值；单选项必须覆盖缺省、每个选项、合法数组和空值，列表必须覆盖单值、多个值及顺序。自动测试使用虚构地址和凭据，真实订阅及设备配置不进入公开测试或 CI。

页面应用验收必须等待 LuCI 的确认请求成功，再读取已确认的配置。仅观察到 UCI 临时写入，不能证明应用成功；在确认前退出浏览器，配置可能由检查式应用自动回滚。

## 下载与分享链接

订阅下载必须同时满足 curl 成功退出、明确的 HTTP 2xx 结果和完整的命令输出。当前命令输出上限为 512 KiB（包括 HTTP 状态尾行），超过上限直接拒绝；不能解析截断前缀后再清理旧节点。失败的来源保留旧节点，其他成功来源仍可独立更新；候选配置继续由现有事务完成生成、核心校验和应用。

手动导入通过只授予写权限的 `share_links_parse` RPC 调用 `share_links.uc`，订阅更新也使用这个模块。解析器不写 UCI、不重启服务；调用者保留全局订阅策略和保存流程。`insecure` 只有明确的 `1`、`true` 才开启，`0`、`false`、缺省及其他值均关闭。URL 参数只解码一次，凭据中的百分号转义、冒号及 Base64 填充不能丢失。HTTP Host 使用支持端口和方括号 IPv6 的校验，并保留原始值。

合并解析入口时，必须逐项核对旧入口的拒绝条件，不能仅比较正常链接的解析结果。分享链接及 SIP008 的 Shadowsocks 加密方式只接受编辑器能表示的集合；自动测试逐一导入编辑器的全部选项并通过真实核心检查，同时拒绝未知方式和缺失值。AnyTLS、Trojan 缺少密码，TUIC、VLESS 缺少身份字段时拒绝导入。HTTP 与 HTTPS 按原协议解析：省略或空端口分别使用 80、443，AnyTLS、Hysteria2（含 hy2 别名）也按协议约定默认使用 443，显式端口原样保留；测试覆盖域名、IPv4、IPv6 和实际生成结果。

节点图只在一次配置生成的只读快照内缓存解析与验证结果。共享依赖只验证一次；循环、缺失节点、非法分组默认值仍报错。新的生成过程创建新模型，不能复用上次生成的缓存。

页面分组、基节点和上游字段使用独立的前端图校验器，其缓存只属于一次字段校验，不能复用后端模型的验证结论。每次调用重新读取当前表单值和 UCI 状态；解析结果和已完成遍历分别缓存，继续保留递归路径检测循环。后端性能测试不能替代这条页面路径的单元测试。

分享链接仅在首个 `://` 处分离协议，路径及名称中的相同字符必须保留。Shadowsocks 的 SIP002 百分号编码、Base64 userinfo 和整串 Base64 分别按各自的编码约定解析：整串 Base64 中的密码是原文，不能再次当成百分号编码解码；外部名称也只解码一次。回归检查需要断言路径、密码及名称的原始值，并验证页面回存和实际生成结果。

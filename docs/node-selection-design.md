# 节点选择与加载边界（设计待实施）

当前节点库有 105 个对象，开发容器运行配置加载 24 个库对象和 2 个系统出站。生成器会从自定义默认出站、启用的路由规则／DNS 服务器／规则集引用递归加载组成员和 detour。旧 enabled routing_node 则仍会全部生成，并不是严格的统一引用模型。非自定义模式从主节点、UDP 节点及 URLTest 成员开始加载，但普通主节点改名 main-out 后，其 detour 依赖收集存在缺口，需要统一收集器。

建议按用户期望保留“路由节点”作为自定义模式的引用清单，改称“启用节点”：从节点库多选、搜索、全选，不再复制协议参数或另造节点。明确选择的根节点及递归依赖进入核心，列表区分手动选择和依赖带入，并显示依赖来源。路由规则和默认出站使用该清单。取消仍被规则引用的项需报出引用位置；组依赖不可在这里单独删掉。全选只是选择全部库对象的快捷操作，仍通过同一依赖校验。

非自定义模式保留现有主节点／UDP 节点选择，无需增加引用清单，也不全量加载库。两类模式共用同一个依赖遍历器，避免主节点别名、组嵌套、Endpoint 与链式出站走不同逻辑。DNS 和规则集下载出站也是加载起点，不能遗漏。

组成员表示候选关系；detour 表示连接代理服务器时使用的上游。A 的上游是 B 时，连接顺序为路由器 → B → A → 目标。协议参数、组成员和链式上游统一由节点设置编辑。解析器、解析策略及接口绑定放节点高级设置，并校验其在当前模式是否可用。组类型不支持的拨号字段不能强行添加。

订阅节点的本地覆盖应独立保存，不被订阅更新覆盖。旧 routing_node 的解析器／接口／上游覆盖需迁移；同一服务器有多条不同链时，应建立明确命名的本地节点变体，而不是修改共享订阅节点导致其他用途改变。

选择时显示依赖预览并校验缺失、默认成员、自引用、间接循环、跨组和 detour 混合循环；生成前再次遍历并检查核心支持类型及 DNS 引用。所有检查通过后才能替换运行配置。依赖节点可以自动带入，无需用户逐个勾选。

本次仅核对并记录该设计，尚未实施引用清单与节点高级字段迁移。已实施的变更仅为 Observability Groups 布局及交互整理。
